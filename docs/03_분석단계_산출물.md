| **사후 조건** | 주문 생성, 결제 완료, 보험가입 요청 이벤트 발행, 배송 예약 시작 |
| **기본 흐름** | 1. 회원이 상품 상세 페이지에서 이용 기간 선택 → 2. 배송 일시/장소 입력 → 3. 보험 옵션 선택 → 4. 쿠폰 적용(선택) → 5. 결제 정보 입력 → 6. 결제 승인 요청 → 7. PG사 승인 → 8. 주문 완료, 보험가입 이벤트 발행 |
| **대안 흐름** | 5a. 재고 소진: 구매 불가 안내, 찜하기 유도. 6a. 결제 실패: 오류 메시지 표시, 재시도 유도 |
| **예외 흐름** | 결제 중 보험가입 조건 미충족 시 → 주문 자동 취소, 결제 환불 처리 |

#### UC-17: 보험 가입 자동 처리

| 항목 | 내용 |
|---|---|

| **유스케이스명** | 보험 가입 자동 처리 |

## 3.3 사용자 시나리오/User Journey

### 3.3.1 구매→보험가입→배송→이용→회수 전 과정 플로우

```mermaid
flowchart TD
    START([회원 로그인]) --> BROWSE[상품 목록/검색]
    BROWSE --> DETAIL[상품 상세 페이지]
    DETAIL --> SELECT_PLAN[이용 기간 선택]
    SELECT_PLAN --> CHECK_AVAIL{차량 가용 여부}
    CHECK_AVAIL -- 가용 --> SET_DELIVERY[배송 일시/장소 설정]
    CHECK_AVAIL -- 불가 --> NOTIFY_WISH[재고 알림 신청/찜]
    SET_DELIVERY --> SELECT_INS[보험 옵션 선택\n기본/프리미엄]
    SELECT_INS --> APPLY_COUPON{쿠폰 보유?}
    APPLY_COUPON -- 있음 --> COUPON_APPLY[쿠폰 적용]
    APPLY_COUPON -- 없음 --> PAYMENT_PAGE
    COUPON_APPLY --> PAYMENT_PAGE[결제 화면]
    PAYMENT_PAGE --> PAYMENT[결제 진행]
    PAYMENT --> PG_RESULT{PG 승인}
    PG_RESULT -- 실패 --> PAY_FAIL[결제 실패 안내\n재시도 유도]
    PG_RESULT -- 성공 --> ORDER_COMPLETE[주문 완료\n주문번호 발급]
    ORDER_COMPLETE --> KAFKA_ORDER[Kafka: order.created 발행]
    KAFKA_ORDER --> INS_REQUEST[보험가입 요청\n보험사 API 호출]
    INS_REQUEST --> INS_RESULT{보험 가입 결과}
    INS_RESULT -- 실패 --> INS_FAIL[보험가입 실패\n주문취소/환불 Saga]
    INS_RESULT -- 성공 --> INS_COMPLETE[보험 증권 발행\nKafka: insurance.completed]
    INS_COMPLETE --> DELIVERY_SCHEDULE[배송 스케줄 생성\n기사 배정]
    DELIVERY_SCHEDULE --> DELIVERY_NOTIFY[배송 예정 알림\nSMS/앱푸시]
    DELIVERY_NOTIFY --> WAIT_DELIVERY[이용 시작일 대기]
    WAIT_DELIVERY --> DRIVER_DEPART[배송 당일\n탁송기사 출발]
    DRIVER_DEPART --> TRACK[회원 배송 추적 가능]
    TRACK --> VEHICLE_DELIVERED[차량 인도 완료\n기사-회원 상태 확인]
    VEHICLE_DELIVERED --> IN_USE[이용 중]
    IN_USE --> EXPIRY_D3[만료 D-3 알림]
    EXPIRY_D3 --> EXPIRY_D1[만료 D-1 알림]
    EXPIRY_D1 --> EXPIRY_DAY[만료 당일 알림]
    EXPIRY_DAY --> RETURN_SCHEDULE[회수 스케줄 실행]
    RETURN_SCHEDULE --> VEHICLE_RETURNED[차량 회수 완료\nKafka: vehicle.returned]
    VEHICLE_RETURNED --> ORDER_CLOSED[이용권 이용 완료]
    ORDER_CLOSED --> REVIEW[리뷰 작성 유도]
    REVIEW --> END([종료])
```

### 3.3.2 환불 처리 플로우

```mermaid
flowchart TD
    START([회원: 환불 신청]) --> CHECK_STATUS{이용권 상태 확인}
    CHECK_STATUS -- 배송 전 --> CALC_PRE[이용 전 환불율 계산\n결제 후 24h 이내 → 100%\n배송 D-3 이상 → 70% 등]
    CHECK_STATUS -- 이용 중 --> CHECK_USAGE{이용 경과율}
    CHECK_USAGE -- 75% 초과 --> NO_REFUND[환불 불가 안내]
    CHECK_USAGE -- 75% 이하 --> CALC_MID[일할 환불금액 산정\n잔여일 × 일 요금 × 환불율]
    CHECK_STATUS -- 이용 완료 --> NO_REFUND
    CALC_PRE --> SHOW_AMOUNT[예상 환불금액 표시]
    CALC_MID --> SHOW_AMOUNT
    SHOW_AMOUNT --> CONFIRM{회원 확인}
    CONFIRM -- 취소 --> END_CANCEL([신청 취소])
    CONFIRM -- 확인 --> REFUND_REQ[환불 신청 등록\nREFUND 테이블 저장]
    REFUND_REQ --> KAFKA_REF[Kafka: refund.requested 발행]
    KAFKA_REF --> PG_REFUND[PG사 환불 API 호출]
    PG_REFUND --> PG_RESULT{PG 환불 결과}
    PG_RESULT -- 실패 --> MANUAL_Q[관리자 수동처리 큐 등록\n알림 발송]
    PG_RESULT -- 성공 --> INS_CANCEL[보험 해지 요청\n보험사 API]
    INS_CANCEL --> RETURN_CREATE{이용 중이었나?}
    RETURN_CREATE -- 예 --> EARLY_RETURN[조기 회수 스케줄 생성]
    RETURN_CREATE -- 아니오 --> SKIP_RETURN[회수 불필요]
    EARLY_RETURN --> KAFKA_COMPLETE[Kafka: refund.completed 발행]
    SKIP_RETURN --> KAFKA_COMPLETE
    KAFKA_COMPLETE --> NOTIFY[회원 환불 완료 알림\nSMS/이메일]
    NOTIFY --> END([환불 완료])
```
