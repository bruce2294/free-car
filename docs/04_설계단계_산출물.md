## 4.6 시퀀스 다이어그램: 장바구니 ~ 주문 ~ 쿠폰엔진 ~ 결제 및 분산 트랜잭션(Saga)

```mermaid
sequenceDiagram
    actor U as 고객
    participant FE as Vue Frontend
    participant CART as CartService
    participant COUPON as CouponEngine
    participant ORDER as OrderService
    participant REDIS as Redis (분산락)
    participant PG as 토스페이먼츠
    participant DB as MySQL DB
    participant KAFKA as Kafka

    U->>FE: 1. 장바구니에서 [선택 주문하기] 클릭
    FE->>COUPON: POST /api/v1/orders/calculate-preview (아이템ID목록, 쿠폰ID, 포인트사용액)
    COUPON-->>FE: 실시간 시뮬레이션 결과 (원가, 정률/정액 감면액, 보증금, 최종결제액)
    
    U->>FE: 2. 최종 주문서 확인 및 [결제하기] 클릭
    FE->>ORDER: POST /api/v1/orders (장바구니아이템ID, 수령인정보, 쿠폰ID, 포인트)
    
    ORDER->>REDIS: 차량ID 기준 Redisson 분산락 획득 (SETNX 10초)
    alt 락 획득 실패 (동시 예약 발생)
        REDIS-->>ORDER: 락 획득 실패
        ORDER-->>FE: 409 Conflict (선택하신 차량이 다른 고객에 의해 결제 진행 중입니다)
    else 락 획득 성공
        ORDER->>DB: orders 마스터 레코드 생성 (상태: PAYMENT_PENDING)
        ORDER->>DB: order_item 항목 생성 & 구매 당시 vehicle_snapshot(JSON) 영구 보존
        ORDER->>DB: order_coupon 적용 내역 저장 및 user_coupon 상태 'USED' 변경
        ORDER->>CART: 장바구니에서 주문된 cart_item 삭제
        ORDER->>REDIS: 분산락 해제
        ORDER-->>FE: orderNo, finalPaymentAmount, 토스페이먼츠 파라미터 반환
    end

    FE->>PG: 3. 토스페이먼츠 결제창 호출 및 카드 인증 승인
    PG-->>FE: paymentKey 반환
    
    FE->>ORDER: 4. POST /api/v1/payments/confirm (paymentKey, orderNo, amount)
    ORDER->>PG: 결제 최종 승인 API 호출 (WebClient)
    PG-->>ORDER: 승인 성공 (approvedAt, 영수증URL)
    ORDER->>DB: payment 레코드 저장 & orders 상태 'PAID' 전이
    ORDER->>DB: order_status_history 기록 (PAYMENT_PENDING -> PAID)
    ORDER->>KAFKA: 이벤트 발행 (order.paid)
    ORDER-->>FE: 결제 완료 응답

    Note over KAFKA,DB: 5. 비동기 Saga 분산 트랜잭션 처리
    KAFKA->>DB: 보험 가입 처리 (InsuranceProcessJob) -> DB손해보험 API 호출 및 증권번호 저장
    KAFKA->>DB: 탁송 스케줄 생성 (DeliverySchedulingJob) -> 기사 배정 및 알림톡 발송
```
